1. Project Overview
================================================================================

Chat Sphere: A Full-Stack Real-Time Messaging Web Application with WebSocket
Communication, Group Collaboration, and Expense Splitting

Chat Sphere is a full-stack real-time messaging web application built on the MERN-style
stack (React, Express, Node.js, and MongoDB) that delivers a comprehensive communication
platform, enabling users to exchange instant text messages, share images and files via
Cloudinary, create and manage group conversations, track online presence and message
delivery status, split expenses within groups, and schedule messages for future delivery —
all from a single responsive, mobile-first web dashboard powered by Socket.IO for
bidirectional real-time communication. A background scheduler service runs server-side
every 30 seconds to dispatch due messages and expire temporary groups automatically.

2. Problem Statement
================================================================================

Modern instant messaging has become an essential communication tool for students and
working professionals, yet building a reliable, feature-rich messaging platform involves
solving several complex engineering challenges. Specifically:

•  Latency in Message Delivery: Traditional HTTP request-response cycles introduce
   unacceptable delays for chat applications. Users expect sub-second delivery with
   real-time typing indicators, read receipts, and online/offline presence — features
   that require persistent bidirectional communication channels.

•  Lack of Real-Time Presence Tracking: Users need to know whether their contacts
   are currently online, when they were last active, and whether they are actively
   typing a response. Most basic web applications do not support these real-time
   presence features natively.

•  Fragmented Group Communication: Creating group conversations, managing
   participants (adding/removing members), and ensuring all members receive
   messages simultaneously with correct unread counts requires careful database
   schema design and event-driven broadcasting.

•  File and Media Sharing Complexity: Users expect to share images, documents, and
   voice messages seamlessly within conversations. Handling file uploads, enforcing
   size limits, storing media in cloud storage, and rendering previews across device
   types adds significant complexity.

•  Expense Management in Groups: Group participants frequently need to split shared
   costs (dinners, trips, bills) fairly. Tracking who paid, who owes what, supporting
   multiple split strategies (equal, custom amount, percentage), and keeping settlement
   history linked to the relevant group conversation is a non-trivial engineering
   problem that most messaging applications do not address natively.

•  Delayed and Scheduled Communication: Users often need to compose messages in
   advance and deliver them at a specific future time. Building a reliable server-side
   scheduler that survives restarts, handles failures gracefully, and emits real-time
   socket events upon dispatch requires careful background service design.

•  Security Concerns: User credentials must be securely hashed, authentication tokens
   must be tamper-proof, API endpoints must be rate-limited to prevent abuse, and
   messages should have basic encryption at rest.

Chat Sphere resolves these issues by unifying text messaging, media sharing, group
collaboration, presence tracking, expense splitting, and scheduled message delivery
under a single secure, cloud-deployed web application with Socket.IO-powered real-time
communication and JWT-based authentication.

3. Objectives
================================================================================

The project is guided by the following specific objectives:

1. To design and implement secure user registration and login using JWT (JSON Web
   Tokens) stored in localStorage with password hashing using Bcrypt (12 salt rounds)
   and token verification middleware on all protected API routes.

2. To implement real-time bidirectional messaging using Socket.IO, enabling instant
   message delivery, delivery acknowledgments, and read receipts (single-tick,
   double-tick, and blue-tick status indicators).

3. To build a real-time presence system that tracks user online/offline status and
   "last seen" timestamps, broadcasting presence changes to all connected contacts
   via Socket.IO events.

4. To develop typing indicators that display animated "typing..." feedback when a
   contact is composing a message, with automatic timeout-based clearing.

5. To implement complete CRUD operations for conversations, supporting both direct
   (one-to-one) and group conversations, including group creation with a multi-step
   modal (member selection → group info), member addition/removal by the admin,
   and the ability to leave a group.

6. To build a rich message input system supporting text messages, emoji selection
   (via emoji-picker-react), image and document attachments (uploaded to Cloudinary
   with a 10MB limit), voice message recording via the MediaRecorder API, and
   clipboard paste for images.

7. To implement message management features including message deletion ("This
   message was deleted"), in-chat message search with match navigation, chat
   clearing, and conversation deletion.

8. To build a group expense splitting system that allows group members to log shared
   costs, choose a split strategy (equal, custom amount, or percentage), designate
   who paid, track individual settlement status, and view net balance summaries —
   with real-time updates broadcast via Socket.IO to all group members.

9. To implement a server-side scheduled message system allowing users to compose
   messages in advance and deliver them at a specified future date and time. A
   background polling service (30-second interval) dispatches due messages, emits
   Socket.IO events to recipients, and handles cancellation and group expiry.

10. To support temporary groups with configurable expiration dates, after which the
    group becomes read-only. The scheduler automatically marks expired groups, emits
    a group:expired socket event to all participants, and inserts a system message.

11. To create a notifications panel that aggregates incoming message notifications with
    sender information, timestamps, read/unread status, and direct navigation to the
    relevant conversation.

12. To implement a profile management system allowing users to update their display
    name, about status, and avatar (uploaded to Cloudinary), with changes reflected
    in real-time across all conversations.

13. To support dark/light theme toggling with persistence across sessions using
    Zustand state management and CSS custom properties.

14. To deploy the application to cloud platforms — frontend on Vercel, backend on
    Render, and database on MongoDB Atlas — ensuring zero-downtime production
    availability.

4. Motivation and Need for the Project
================================================================================

Instant messaging has become the primary communication channel for over 2 billion
users worldwide. Understanding the full engineering stack behind modern messaging
platforms — from real-time WebSocket communication to optimistic UI updates and cloud
media storage — provides invaluable learning opportunities for computer science
students.

Furthermore, this project provides a concrete opportunity to apply modern full-stack web
technologies — JWT-based authentication, Socket.IO event-driven architecture, Zustand
state management, Cloudinary CDN integration, and responsive UI design with Tailwind
CSS — to a real-world, high-concurrency communication problem.

The need for the project can therefore be summarised as: (a) a single, secure, responsive
web dashboard that enables instant text messaging, media sharing, and group collaboration;
(b) real-time, event-driven communication using WebSockets
instead of traditional HTTP polling, ensuring sub-second message delivery and live
presence tracking; and (c) a production-grade deployment architecture that separates
frontend, backend, and database across managed cloud services for scalability and
reliability.

powered real-time communication. However, existing systems typically address individual
aspects — either real-time messaging, or file sharing, or authentication — in isolation.
There is a notable absence of integrated platforms that combine all these features within
a single, unified full-stack application.

•  Feature Completeness Gap: Implements the full messaging lifecycle — typing
   indicators, delivery acknowledgments, read receipts, message deletion, in-chat
   search, and conversation management — rather than basic send/receive only.



•  User Experience Gap: Provides a production-grade UI with glassmorphism design,
   dark/light themes, responsive mobile-first layout, emoji picker, voice recording,
   and smooth animations — going beyond basic academic prototypes.

================================================================================

Development spanned eight distinct phases, ensuring database modularity and secure
real-time event integration.

7.1 Requirement Analysis

Functional requirements (authentication, real-time messaging, group conversations, media
sharing, notifications, profile management) and non-functional
requirements (sub-second message latency, security, scalability, responsive design,
accessibility) were identified from the problem statement and refined against the
literature survey gaps identified in Section 5.

7.2 System Design

A layered architecture (Section 6) was designed first, followed by the API contract — six
route groups, each exposing REST endpoints under distinct base paths (/auth, /users,
/conversations, /messages, /expenses, /scheduled-messages) — and the Socket.IO event
contract (message:send, message:new, message:read, typing:start, typing:stop,
user:online, user:offline, expense:new, expense:settled, group:expired).
The React component hierarchy (App → ChatDashboard → Sidebar + ChatWindow, with modal
overlays for ProfileSettings, GroupInfo, CreateGroupModal, NotificationsPanel,
ExpensePanel, ExpenseSplitModal, and ScheduledMessagesPanel) was then mapped out.

7.4 Backend Development

The Express backend was implemented module-by-module:

•  Auth Routes (/api/auth): Registration with input validation (express-validator),
   password hashing (bcrypt), JWT token generation, login with credential verification,
   token verification endpoint (/check), and logout.

•  User Routes (/api/users): User search with query filtering, profile retrieval and
   update, avatar upload to Cloudinary, user blocking/unblocking.

•  Conversation Routes (/api/conversations): Fetch all user conversations with
   populated participants and last message, create direct conversations (with duplicate
   prevention), create group conversations (with optional expiresAt for temporary
   groups), update group info, add/remove group members.

•  Message Routes (/api/messages): Fetch paginated messages per conversation,
   send messages (with Cloudinary upload for media types), mark messages as read,
   delete messages (soft delete), upload files.

•  Expense Routes (/api/expenses): Create expense (POST /), fetch group expenses
   (GET /:conversationId), settle a user's split (PUT /:id/settle), and fetch net
   balance summary (GET /:conversationId/summary). Expense creation validates group
   membership, calculates splits per chosen strategy, auto-posts a system message
   to the group chat, and broadcasts expense:new via Socket.IO.

•  Scheduled Message Routes (/api/scheduled-messages): Create a scheduled
   message with a future scheduledAt datetime (POST /), list the user's pending
   scheduled messages (GET /), update content/time (PUT /:id), and cancel (DELETE
   /:id). Validation rejects past scheduledAt values.

•  Background Scheduler Service (schedulerService.js): A setInterval-based
   polling service started once at server boot. Runs every 30 seconds to:
   (1) Find ScheduledMessage documents with status=pending and scheduledAt ≤ now,
   create real Message documents, emit socket events to all participants, and
   mark scheduled messages as sent.
   (2) Find Conversation documents where groupInfo.expiresAt ≤ now and
   isExpired=false, mark them expired, insert a system message, and emit
   group:expired to all participants.

•  Socket Event Handlers: Three event modules — chatEvents (message sending,
   delivery acknowledgment, read receipts, message deletion), typingEvents (start/
   stop typing broadcasts), presenceEvents (online/offline status with lastSeen
   update) — orchestrated by socketHandler (connection lifecycle, room joining,
   and session-based forced logout).

•  Middleware: JWT authentication (protectRoute), centralized error handler, rate
   limiter (on auth and upload routes), and request validation.

7.6 Integration

The frontend and backend were integrated through Axios calls to relative API paths;
in local development, Vite's dev-server proxy forwards these to the Express server on
port 4000, while in production, Vercel rewrite rules forward the same paths to the
deployed Render backend, requiring no code changes between environments. Socket.IO
connects directly to the backend URL with JWT token-based authentication handshake.

7.7 Testing

Each module was tested using Postman for API endpoint verification (registration, login,
conversation creation, message sending, file upload) alongside manual UI testing of every
component interaction — message delivery/read status, typing indicators, group member
management, voice recording, file sharing, theme toggling, and responsive breakpoints
on mobile/tablet/desktop viewports.

7.8 Deployment

The backend was configured via environment variables (MONGODB_URI, JWT_SECRET,
CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET, CLIENT_URL,
NODE_ENV) and deployed on Render with a MongoDB Atlas connection string. The frontend
was built with Vite (npm run build) and deployed on Vercel with environment variables
(VITE_API_URL, VITE_SOCKET_URL) pointing to the Render backend.

8. Page-by-Page Description
================================================================================

8.1 Login Page (/login)

The Login Page presents a clean, glassmorphism-styled form centred on a vibrant green
gradient background with decorative blur orbs. The page displays the application logo
(chat bubble icon) and brand name at the top, followed by a card containing email and
password input fields. The password field includes a show/hide toggle button. A gradient
"Sign In" button submits the form and shows a spinner during loading. Below the form,
a link navigates to the Signup page. Upon successful authentication, a JWT token is stored
in localStorage, the Socket.IO connection is established, and the user is redirected to the
Chat Dashboard.

8.2 Signup Page (/signup)

The Signup Page mirrors the Login Page's glassmorphism aesthetic with a different gradient
palette (emerald to teal). It presents four input fields: Full Name (minimum 2 characters),
Email, Password (minimum 6 characters), and Confirm Password. Real-time client-side
validation highlights the confirm password field in red when passwords do not match, with
an inline error message. The "Create Account" button is disabled until passwords match.
On successful registration, the user is automatically logged in, the Socket.IO connection
is established, and they are redirected to the Chat Dashboard.

8.3 Chat Dashboard (/ — Main Application)

The Chat Dashboard is the primary application screen, structured as a modern
two-panel layout within a max-width container. A green gradient header bar spans the top.
The left panel contains the Sidebar (conversation list), and the right panel displays either
the active ChatWindow or an EmptyChat welcome screen. On mobile devices (< 768px),
only one panel is visible at a time — the sidebar when no conversation is selected, and
the chat window when a conversation is active (with a back button to return). The
dashboard also mounts the ProfileSettings panel and NotificationsPanel as overlay
components.

8.4 Sidebar (Left Panel)

The Sidebar occupies the left 420–480px of the dashboard and consists of three sections:

•  Header Row: Displays the current user's avatar (clickable to open Profile Settings),
   followed by action buttons for New Group, Theme Toggle, Notifications (with unread
   badge), and a three-dot menu (Profile Settings, New Group, Logout).

•  Search Bar: A rounded search input with a magnifying glass icon. Typing a query
   switches the list below from ChatList to SearchUsers, showing matching users from
   the database (debounced API call). Selecting a search result starts or opens a
   direct conversation.

•  Conversation List (ChatList): Displays all the user's conversations sorted by most
   recent activity. Each ChatListItem shows the contact/group avatar (with online
   green dot for direct chats), conversation name, last message preview (truncated),
   timestamp, and an unread message count badge. Clicking a conversation sets it as
   the active conversation and loads its messages.

8.5 Chat Window (Right Panel)

The Chat Window fills the right side of the dashboard and is composed of three vertically
stacked sections:

•  Chat Header: Shows the contact's avatar, name, and status text (online, "last seen
   [time]", "typing...", or "[N] participants" for groups). Action buttons include
   Search Messages and a three-dot menu (Contact Info, Clear Chat,
   Delete Chat). For group chats, clicking the header opens GroupInfo; for direct
   chats, it opens the ProfileModal.

•  Message List: Displays messages in a scrollable container with date separators
   ("Today", "Yesterday", or formatted dates). Messages from the current user appear
   on the right (green bubbles) and received messages on the left (white/dark bubbles).
   Each MessageBubble shows the message content, timestamp, and delivery status
   indicators (single grey tick = sent, double grey tick = delivered, double blue tick =
   read). Image messages render as clickable thumbnails, file messages show a download
   card with filename and size, voice messages display an audio player, and deleted
   messages show italicised "This message was deleted" text. Scrolling up triggers
   infinite scroll to load older messages. A highlighted message (from search) auto-
   scrolls into view with a visual pulse effect.

•  Message Input: A bottom bar containing an emoji button (opens a full emoji picker
   popup), an attachment button (opens a menu with Photo and Document options), a
   multi-line text input area (auto-resizing up to 128px), a Clock button to schedule
   the message for a future date and time (opens a native datetime picker; scheduled
   messages are posted to the server with the chosen scheduledAt), and a Send button
   (appears when text is entered) or Microphone button (appears when text is empty,
   triggers voice recording). During voice recording, a red pill-shaped indicator shows
   elapsed time with a stop button. File previews appear above the input bar before
   sending. If the contact is blocked, the input is replaced with a "You blocked this
   contact" message and an unblock button.

8.6 In-Chat Message Search

When the search icon in the Chat Header is clicked, a search bar slides down below the
header. As the user types, messages matching the query are highlighted and a counter
displays "X of Y" matches. Up/Down arrow buttons (and Enter/Shift+Enter keyboard
shortcuts) navigate between matches, auto-scrolling the message list to the highlighted
message. Pressing Escape or the close button dismisses the search.

8.7 Group Info Modal

Opened by clicking the header of a group conversation. Displays the group's avatar, name,
description, and participant count at the top. If the group has an expiry date set, a
countdown or expiry timestamp is shown. Below, a scrollable participant list shows each
member's avatar, name, online status, and about text. The group admin is tagged with
an "Admin" badge. If the current user is the admin, an "Add Participant" button appears,
expanding a search section to find and add new members with a chip-based selection UI.
The admin can also remove individual members. If the group is expired (read-only), member
management controls are hidden. At the bottom, a "Leave Group" button allows any
non-expired group member to exit the group.

8.8 Create Group Modal

Accessed via the group icon or "New Group" menu item in the Sidebar. A two-step modal
guides the user through group creation:

•  Step 1 — Select Members: A search input finds registered users. Search results
   display user avatar, name, and about text. Clicking a user adds them to a chip
   bar above the search; clicking the chip's X removes them. A minimum of 2 members
   is required. The "Next" button shows the selected count and proceeds to Step 2.

•  Step 2 — Group Info: Input fields for Group Name (required, max 50 characters)
   and Group Description (optional, max 150 characters). "Back" returns to Step 1;
   "Create Group" submits the request and opens the newly created group conversation.

8.9 Profile Settings Panel

A full-height slide-in panel from the left (with backdrop overlay) containing:

•  A green gradient header with "Profile" title and back arrow.
•  A large circular avatar with a camera overlay on hover (click to upload a new photo
   to Cloudinary, max 5MB, with a loading spinner during upload).
•  An editable "Your Name" field with an underline input style (max 50 characters),
   with helper text explaining visibility.
•  An editable "About" field (max 150 characters).
•  A read-only Email display.
•  A "Save Changes" button with gradient styling and loading state.

8.10 Expense Panel

A full-height slide-in panel from the right (only available in group conversations). The
header displays the group name and an "Add" button to open the ExpenseSplitModal. The
top section shows a balance summary card with "You are owed" (green) and "You owe" (red)
totals, plus a per-person settlement detail list. Below, an expense history list shows each
expense card with description, who paid, date, total amount, and a settled/unpaid badge
(e.g. "2/4 Paid"). Clicking a card expands a per-member splits breakdown showing each
person's share and paid/unpaid status. If the current user has an unsettled split, a
"Mark Paid" button appears inline.

8.11 Expense Split Modal

A modal dialog opened from the Expense Panel or Chat Header menu. The form contains:
a description input, amount and currency selector, a "Paid By" dropdown (any group
member), a split method selector (Equally / Exact Amounts / By Percentage), and a
scrollable participant list. For "Equally", each selected member shows their per-person
amount in real time. For "Exact Amounts" or "By Percentage", each row has an editable
input with live validation showing the current total vs. required total. A disabled submit
button prevents invalid submissions.

8.12 Scheduled Messages Panel

A full-height slide-in panel from the left listing all pending scheduled messages across all
conversations. Each card shows the target conversation name, message preview (or file
type icon), and a human-readable countdown ("In 2h 15m — 3:30 PM" or date for future
days). A "Cancel" button marks the scheduled message as cancelled. When empty, a
placeholder with instructions is shown.

8.13 Notifications Panel

A full-height slide-in panel from the right showing a chronological list of notifications.
Each notification card displays the sender's avatar, notification title (sender name or
group name), message body preview, timestamp, and an unread indicator dot. Unread
notifications have a subtle tinted background. Clicking a notification navigates to the
relevant conversation and closes the panel. A "Clear all" button removes all notifications.
When empty, a placeholder graphic with "You're all caught up!" message is shown.

8.14 Theme Toggle

A toggle button in the Sidebar header switches between light and dark mode. The theme
preference is persisted via Zustand store and restored on app reload. In dark mode, the
entire application switches to a dark colour palette with adjusted backgrounds, text
colours, borders, and input fields — while maintaining the signature Chat Sphere green
accent colour throughout.
